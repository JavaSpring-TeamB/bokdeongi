# 복덩이(Bokdeongi) — 프론트엔드 디자인 가이드

**문서 버전:** v1.0
**작성 기준:** 복덩이 화면설계(ver.3)
**적용 범위:** 복덩이 웹사이트 전체 화면
**개발 환경:** HTML5 / CSS3 / Vanilla JavaScript

---

## 1. 디자인 가이드 목적

본 문서는 복덩이 프로젝트의 전체 웹페이지에서 일관된 디자인을 유지하기 위한 공통 규칙을 정의한다.

Codex 및 모든 프론트엔드 개발자는 새로운 페이지를 구현하거나 기존 페이지를 수정할 때 반드시 본 문서를 확인하고 준수해야 한다.

### 핵심 원칙

1. 모든 페이지의 헤더와 내비게이션은 동일한 디자인을 사용한다.
2. 동일한 역할의 제목, 부제목, 본문은 동일한 글자 크기와 굵기를 사용한다.
3. 모든 색상은 본 문서에서 정의한 색상 팔레트만 사용한다.
4. 버튼, 카드, 입력창, 배지 등의 공통 UI 구성요소는 동일한 스타일을 사용한다.
5. 페이지별로 콘텐츠 너비, 정렬 방식, 여백 기준을 통일한다.
6. 기존 화면설계의 디자인을 최대한 충실하게 재현한다.
7. 페이지별 새로운 디자인 스타일을 임의로 만들지 않는다.
8. 디자인 변경은 공통 디자인 규칙에 반영한 후 전체 페이지에 일관되게 적용한다.

**가장 중요한 규칙: 같은 역할을 수행하는 UI 요소는 어느 페이지에 있더라도 동일한 스타일이어야 한다.**

## 2. 디자인 콘셉트

### 2.1 전체 디자인 방향

- 공공기관 홈페이지처럼 신뢰감 있는 디자인
- 흰색 배경 중심의 깔끔한 화면
- 연한 민트색과 녹색을 활용한 포인트 디자인
- 가독성을 우선한 정보 중심 레이아웃
- 복덩이 캐릭터를 활용한 친근한 분위기
- 불필요한 장식을 제거한 미니멀 디자인

### 2.2 디자인 제한

다음 사항은 금지한다.

- 페이지마다 다른 색상 팔레트 사용
- 임의의 글꼴 또는 글자 크기 사용
- 불필요한 그라데이션 추가
- 과도한 그림자 효과
- 의미 없는 애니메이션
- 과도하게 둥근 카드와 버튼
- 기존 화면설계에 없는 장식 요소 추가
- 공통 컴포넌트를 페이지마다 다른 형태로 구현

## 3. 화면 크기 및 레이아웃

### 3.1 기본 화면 크기

| 항목 | 규칙 |
|---|---|
| PC 디자인 기준 | 1440px |
| 콘텐츠 최대 너비 | 1280px |
| 콘텐츠 최소 좌우 여백 | 24px (PC) |
| 공통 헤더 높이 | 72px |
| 홈 메인 배너 표시 기준 | 1280 × 320px |
| 기본 섹션 간격 | 32px |
| 카드 간격 | 16px |
| 카드 내부 여백 | 24px |

PC 화면에서는 메인 콘텐츠가 중앙에 정렬되어야 한다.

브라우저 너비가 1440px보다 커지더라도 콘텐츠는 최대 1280px을 유지한다.

브라우저 너비가 작아질 경우 콘텐츠는 화면 너비에 맞춰 유동적으로 변경한다.

화면 크기를 1440px로 강제 고정하지 않는다.

### 3.2 공통 컨테이너

모든 페이지는 공통 `.container` 클래스를 사용한다.

권장 CSS:

```css
.container {
  width: calc(100% - 48px);
  max-width: 1280px;
  margin-inline: auto;
}
```

### 3.3 반응형 기준

| 화면 | 너비 | 구성 |
|---|---|---|
| PC | 1025px 이상 | 기본 가로형 레이아웃 |
| 태블릿 | 768~1024px | 2열 중심 레이아웃 |
| 모바일 | 767px 이하 | 1열 레이아웃 |

반응형 규칙:

- 모바일에서 메뉴는 햄버거 메뉴로 변경
- 대시보드 카드는 1열 배치
- 배너의 텍스트와 버튼은 화면 크기에 따라 재배치
- 글자나 버튼이 화면 밖으로 벗어나지 않도록 한다
- 모바일 가로 스크롤 금지
- 작은 화면에서도 정보의 중요도와 읽는 순서를 유지한다

## 4. 공통 색상 규칙

### 4.1 색상 사용 원칙

**아래 색상 팔레트에 정의되지 않은 색상은 임의로 사용하지 않는다.**

모든 색상은 CSS 변수를 통해 사용한다.

디자인 변경이 필요한 경우 새로운 색상 코드를 직접 입력하지 말고 공통 팔레트를 수정한다.

### 4.2 기본 색상 팔레트

| 색상 이름 | HEX | 사용 목적 |
|---|---|---|
| Primary | `#176B45` | 주요 버튼, 강조 텍스트 |
| Primary Hover | `#115536` | 버튼 호버 |
| Primary Light | `#EAF6EE` | 연한 녹색 배경 |
| Mint Light | `#F3FAF5` | 안내 카드, 보조 배경 |
| White | `#FFFFFF` | 기본 배경, 카드 |
| Text Primary | `#222222` | 제목, 주요 본문 |
| Text Secondary | `#667085` | 부제목, 보조 설명 |
| Border | `#E5EAE7` | 카드, 입력창, 구분선 |
| Surface | `#F8FAF9` | 중립 영역 배경 |

### 4.3 상태 표시 전용 색상

상태 전달이 필요한 경우에만 사용한다.

| 상태 | 색상 | HEX |
|---|---|---|
| 성공 / 충족 | Green | `#176B45` |
| 확인 필요 / 조건부 | Amber | `#B7791F` |
| 오류 / 미충족 | Red | `#C24141` |
| 정보 / 결과 발표 | Blue | `#2563A6` |

상태 색상은 일반적인 장식에 사용하지 않는다.

상태를 색상만으로 전달하지 않고 텍스트를 함께 표시한다.

예시:

- 해당
- 조건부
- 확인 필요
- 미충족
- 마감 임박
- 신청 완료

### 4.4 CSS 변수

공통 CSS에 다음 변수를 정의한다.

```css
:root {
  --color-primary: #176B45;
  --color-primary-hover: #115536;
  --color-primary-light: #EAF6EE;
  --color-mint-light: #F3FAF5;

  --color-white: #FFFFFF;
  --color-text: #222222;
  --color-text-secondary: #667085;
  --color-border: #E5EAE7;
  --color-surface: #F8FAF9;

  --color-success: #176B45;
  --color-warning: #B7791F;
  --color-danger: #C24141;
  --color-info: #2563A6;
}
```

실제 색상 변경은 위 변수 정의에서만 수행한다.

## 5. 글꼴 및 타이포그래피

### 5.1 기본 글꼴

전체 웹사이트의 기본 글꼴은 `Pretendard`로 통일한다.

Pretendard를 사용할 수 없는 경우 아래 대체 글꼴을 사용한다.

```css
font-family:
  'Pretendard',
  'Noto Sans KR',
  sans-serif;
```

별도 글꼴은 도입하지 않는다.


### 웹폰트 적용 규칙

- 프로젝트 기본 폰트는 Pretendard Variable로 통일한다.
- 폰트 파일은 fonts/PretendardVariable.woff2를 사용한다.
- 웹폰트는 css/common.css에서 @font-face로 선언한다.
- 모든 페이지에서 동일한 폰트를 사용한다.
- 페이지별 CSS에 별도 font-family를 선언하지 않는다.
- 기존 폰트를 임의로 변경하지 않는다.
- 웹폰트 로딩 실패 시 시스템 sans-serif로 대체한다.


### 5.2 글자 크기 규칙

동일한 역할의 텍스트는 모든 페이지에서 같은 크기와 굵기를 사용한다.

| 역할 | 크기 | 굵기 | 줄 높이 |
|---|---|---|---|
| 메인 배너 제목 | 32px | 700 | 1.4 |
| 페이지 제목 (H1) | 30px | 700 | 1.4 |
| 섹션 제목 (H2) | 24px | 700 | 1.4 |
| 카드 제목 (H3) | 20px | 600 | 1.5 |
| 본문 | 18px | 400 | 1.6 |
| 부제목 / 설명 | 16px | 400 | 1.6 |
| 버튼 텍스트 | 16px | 600 | 1.4 |
| 보조 정보 / 캡션 | 14px | 400 | 1.5 |
| 주요 금액 / 통계 | 30px | 700 | 1.4 |

### 5.3 제목 사용 규칙

**페이지 제목**

- 모든 페이지에서 동일한 글자 크기를 사용한다.
- H1 스타일을 적용한다.
- 페이지의 핵심 목적을 설명한다.

예시:

- 복지 혜택 찾기
- 맞춤 혜택 추천
- 신청 현황
- 쉬운 말 번역기
- 마이페이지

**섹션 제목**

- H2 스타일을 사용한다.
- 페이지 내부 주요 콘텐츠 영역을 구분한다.

예시:

- 이번 주 혜택 요약
- 나의 신청 현황
- 신청 일정 캘린더
- 필요한 서류

**카드 제목**

- H3 스타일을 사용한다.
- 카드 내부 항목명을 표시한다.

### 5.4 타이포그래피 제한

- 동일한 역할의 제목에 다른 크기 사용 금지
- 특정 페이지만 글씨를 과도하게 크게 표시하지 않는다
- 임의의 `font-size` 값 직접 지정 지양
- 제목은 기본적으로 왼쪽 정렬
- 한 페이지에 여러 개의 메인 H1 사용 지양
- 글자 굵기는 400, 500, 600, 700을 기준으로 사용
- 가독성을 해치는 작은 글씨 사용 금지

모바일에서는 필요한 경우 메인 제목 크기를 줄일 수 있다.

단, 같은 역할의 요소는 동일한 반응형 크기 규칙을 적용한다.

## 6. 공통 헤더 디자인

### 6.1 기본 원칙

**모든 페이지는 동일한 공통 헤더를 사용한다.**

페이지마다 개별적으로 헤더를 새로 디자인하지 않는다.

헤더의 높이, 로고 크기, 메뉴 순서, 글자 크기, 색상, 간격을 통일한다.

### 6.2 헤더 기본 규격

| 항목 | 기준 |
|---|---|
| 헤더 높이 | 72px |
| 배경색 | White |
| 하단 테두리 | 1px Border |
| 로고 위치 | 왼쪽 |
| 메뉴 위치 | 중앙 |
| 사용자 메뉴 | 오른쪽 |
| 메뉴 글자 크기 | 14px |
| 메뉴 굵기 | 500 |
| 활성 메뉴 | Primary |

### 6.3 공통 메뉴 순서

1. 홈
2. 복지 혜택 찾기
3. 맞춤 혜택 추천
4. 신청 현황
5. 쉬운 말 번역기
6. 마이페이지(사용자 영역)

'AI 신청 도우미'는 헤더에 별도 메뉴로 추가하지 않는다.

AI 신청 도우미는 혜택 상세 화면에서 진입한다.

### 6.4 활성 메뉴 표시

현재 페이지에 해당하는 메뉴만 강조한다.

활성 메뉴 규칙:

- 글자색: Primary
- 하단 강조선 또는 연한 녹색 배경 중 하나를 공통으로 선택
- 비활성 메뉴: 기본 텍스트 색상
- 마우스 호버: Primary

활성 메뉴 디자인은 모든 페이지에서 동일하게 적용한다.

### 6.5 헤더 재사용

헤더 HTML 구조와 CSS 클래스명을 통일한다.

`common.css`에서 헤더 스타일을 관리한다.

화면별 CSS에서 헤더의 높이, 배경색, 메뉴 크기를 임의로 변경하지 않는다.

## 7. 페이지 상단 안내 배너

### 7.1 공통 디자인

홈을 제외한 주요 페이지의 상단에는 화면설계에 따라 안내 배너를 배치할 수 있다.

공통 규칙:

- 배경: Primary Light 또는 Mint Light
- 제목: H1 스타일
- 설명: 부제목 스타일
- 제목 왼쪽 정렬
- 복덩이 캐릭터는 오른쪽 또는 화면설계 지정 위치
- 배너 모서리 반경: 12px
- 불필요한 장식 추가 금지

### 7.2 페이지별 문구

페이지의 목적에 맞는 제목과 설명을 사용하되, 디자인은 동일하게 유지한다.

예시:

- 복지 혜택 찾기
- 맞춤 혜택 추천
- 신청 현황
- 쉬운 말 번역기
- 마이페이지

### 7.3 홈 메인 배너

홈 대시보드에는 전용 메인 배너를 사용한다.

표시 기준 크기: 1280 × 320px

구성:

- 왼쪽: 메인 안내 문구
- 중앙: 복덩이 캐릭터
- 오른쪽: 바로가기 카드 3개

배너 이미지는 기존 `img/` 폴더의 원본을 사용한다.

**이미지에는 캐릭터와 배경만 포함하며, 텍스트와 버튼은 HTML로 구현한다.**

이미지 원본을 임의로 수정하거나 다른 캐릭터로 대체하지 않는다.

실제 이미지 비율을 확인하고 캐릭터가 잘리지 않게 배치한다.

## 8. 버튼 디자인

### 8.1 버튼 종류

버튼은 다음 세 종류를 기본으로 한다.

**Primary Button**

- 가장 중요한 동작
- 배경: Primary
- 텍스트: White
- 호버: Primary Hover

사용 예시:

- 검색하기
- 다음 단계
- 신청 시작하기
- 저장하기

**Secondary Button**

- 보조 동작
- 배경: White
- 테두리: Primary
- 텍스트: Primary

사용 예시:

- 이전 단계
- 상세 보기
- 취소

**Text Button**

- 중요도가 낮은 보조 동작
- 배경: 투명
- 텍스트: Primary

사용 예시:

- 전체 보기
- 더 알아보기

### 8.2 버튼 규격

| 속성 | 값 |
|---|---|
| 기본 높이 | 44px |
| 작은 버튼 높이 | 36px |
| 글자 크기 | 15px |
| 글자 굵기 | 600 |
| 모서리 반경 | 8px |
| 좌우 여백 | 20px |
| 버튼 간격 | 8px |

### 8.3 버튼 사용 규칙

- 동일한 종류의 버튼은 동일한 디자인 사용
- 버튼 크기를 페이지별로 임의 변경하지 않는다
- Primary 버튼은 한 영역에서 가장 중요한 동작에 사용
- 비활성 버튼은 시각적으로 구별
- 버튼 호버 효과 통일
- 아이콘과 텍스트 간격 일정하게 유지
- 실제 동작이 있는 요소는 button 또는 a 태그 사용

## 9. 카드 디자인

### 9.1 공통 카드 규격

| 속성 | 값 |
|---|---|
| 배경 | White |
| 테두리 | 1px solid Border |
| 모서리 반경 | 12px |
| 내부 여백 | 24px |
| 카드 간격 | 16px |
| 그림자 | 기본적으로 사용하지 않음 |

### 9.2 공통 카드 사용 영역

다음 화면에서 동일한 카드 규칙을 사용한다.

- 홈 지원금 요약
- 홈 주간 혜택 요약
- 신청 현황
- 복지 혜택 검색 결과
- 맞춤 혜택 추천 결과
- 신청 도우미 안내
- 마이페이지 관심 혜택

### 9.3 카드 내부 구성

기본 순서:

1. 카드 제목
2. 보조 설명
3. 주요 정보
4. 상태 배지
5. 필요 시 액션 버튼

카드 안의 정보 간격은 일관되게 유지한다.

카드 제목은 H3 스타일을 사용한다.

### 9.4 카드 디자인 제한

- 카드마다 다른 모서리 반경 금지
- 카드별 임의 배경색 사용 금지
- 강한 그림자 사용 금지
- 과도한 아이콘 추가 금지
- 정보가 적은 카드에 불필요한 장식 추가 금지

## 10. 입력창 및 검색창

### 10.1 기본 입력창

| 속성 | 기준 |
|---|---|
| 높이 | 44px |
| 테두리 | 1px solid Border |
| 모서리 반경 | 8px |
| 내부 좌우 여백 | 14px |
| 글자 크기 | 15px |
| 배경 | White |

### 10.2 입력 상태

- 기본: 회색 테두리
- 포커스: Primary 테두리
- 오류: Danger 테두리 및 오류 문구
- 비활성: 중립 배경
- 성공: 필요한 경우 성공 안내 표시

### 10.3 입력창 공통 원칙

- 라벨은 입력창 상단에 배치
- 필수 항목은 명확하게 표시
- 오류 메시지는 입력창 아래에 표시
- placeholder를 라벨 대신 사용하지 않는다
- 동일한 입력 요소에 동일한 스타일 사용

## 11. 탭 및 필터 디자인

### 11.1 탭 디자인

다음 화면에서 공통 탭 스타일을 사용한다.

- 맞춤 혜택 추천
- 신청 현황
- 복지 혜택 상세
- 쉬운 말 번역기
- 마이페이지

### 11.2 공통 규칙

- 기본 텍스트 크기: 14px
- 선택된 탭: Primary 강조
- 선택되지 않은 탭: Text Secondary
- 선택된 탭은 색상뿐 아니라 배경이나 하단선으로 구별
- 탭 사이 간격 통일
- 탭 변경 시 전체 페이지 레이아웃이 불필요하게 이동하지 않도록 한다

### 11.3 필터

- 체크박스, 드롭다운 등 기본 UI 디자인 통일
- 선택 상태를 명확하게 표시
- 필터 초기화 버튼은 Secondary 또는 Text Button 스타일
- 필터 적용 시 기존 검색 조건을 유지한다

## 12. 상태 배지 디자인

### 12.1 배지 종류

- 해당
- 조건부
- 확인 필요
- 해당 없음
- 신청 중
- 신청 완료
- 마감 임박
- 종료

### 12.2 배지 규칙

- 글자 크기: 12px
- 글자 굵기: 600
- 좌우 여백: 10px
- 상하 여백: 4px
- 모서리 반경: 6px
- 같은 상태에는 같은 색상 사용

색상 의미를 임의로 변경하지 않는다.

예를 들어 '해당'에 녹색을 사용했다면 다른 페이지에서도 동일하게 녹색을 사용한다.

### 12.3 경고 및 오류

경고나 오류 상태를 표현할 때는 반드시 설명 문구를 함께 표시한다.

색상만으로 중요한 정보를 전달하지 않는다.

---

## 13. 아이콘 사용 규칙

### 13.1 아이콘 스타일

- 선형(Line) 아이콘을 기본으로 사용한다.
- 동일한 아이콘 세트를 사용한다.
- 선 두께 및 크기를 통일한다.
- 기본 아이콘 색상은 Primary 또는 Text Secondary 사용
- 불필요하게 화려한 아이콘 사용 금지
- 외부 라이브러리를 추가하지 않는 화면은 Lucide 스타일의 인라인 SVG를 사용한다.
- 인라인 SVG는 `fill="none"`, `stroke="currentColor"`, 동일한 `stroke-linecap` 및 `stroke-linejoin` 값을 사용한다.
- 바로가기·신청 현황처럼 의미 전달이 필요한 아이콘에는 텍스트 레이블을 함께 제공한다.

### 13.2 아이콘 크기

| 용도 | 크기 |
|---|---|
| 작은 보조 아이콘 | 16px |
| 일반 버튼 / 메뉴 아이콘 | 20px |
| 카드 아이콘 | 24px |
| 주요 안내 아이콘 | 32px |

### 13.3 사용 제한

- 같은 기능에 다른 아이콘 사용 금지
- 페이지마다 다른 아이콘 스타일 혼용 금지
- 장식 목적으로 과도하게 사용하지 않는다
- 의미 전달에 필요하지 않은 경우 아이콘을 생략한다

---

## 14. 복덩이 캐릭터 사용 규칙

### 14.1 캐릭터 원칙

복덩이는 프로젝트 고유의 마스코트이다.

캐릭터는 기존에 제공된 원본 이미지를 사용한다.

### 14.2 사용 위치

- 홈 메인 배너
- 로그인
- 회원가입
- 안내 배너
- 검색 결과 없음
- 신청 완료
- 오류 및 빈 상태 안내

### 14.3 캐릭터 사용 제한

- 캐릭터 외형 변경 금지
- 다른 동물 캐릭터로 대체 금지
- 임의의 새로운 캐릭터 생성 금지
- 원본 비율 변경 금지
- 캐릭터가 잘리거나 찌그러지지 않도록 한다
- 텍스트와 겹치지 않도록 배치
- 이미지 파일은 `img/`에서 관리

화면설계의 캐릭터 포즈를 우선적으로 참고한다.

해당 포즈의 원본 이미지가 없는 경우 임의로 유사한 캐릭터를 생성하지 말고 기존 이미지 활용 여부를 확인한다.

### 15.2 정렬 규칙

- 제목과 본문은 기본적으로 왼쪽 정렬
- 통계 수치는 필요에 따라 중앙 정렬 가능
- 같은 줄의 카드 높이는 가능한 한 동일하게 유지
- 정렬 기준을 페이지마다 변경하지 않는다

## 17. 접근성 및 사용자 경험

### 17.1 필수 원칙

- 충분한 색상 대비 유지
- 이미지에 적절한 대체 텍스트 제공
- 키보드로 주요 기능 접근 가능
- 포커스 상태를 명확하게 표시
- 클릭 영역은 충분한 크기로 확보
- 오류 안내를 이해하기 쉽게 작성
- 불필요한 시각적 움직임 최소화

### 17.2 글자 크기 조절

글자 크기 변경 기능을 지원한다.

- 기본 크기 100%
- 사용자 설정에 따른 확대 및 축소
- 상대 단위(rem)를 사용하여 구현
- 확대 시 레이아웃이 깨지지 않도록 한다

### 17.3 다크 모드

향후 다크 모드 적용을 고려하여 색상은 CSS 변수로 관리한다.

다크 모드에서는 배경, 텍스트, 테두리 및 상태 색상이 읽기 편하도록 대응해야 한다.

개별 페이지에서 임의로 다크 모드 색상을 정의하지 않는다.

---

## 18. CSS 관리 규칙

### 18.1 공통 CSS

`css/common.css`에 다음 항목을 정의한다.

- 색상 변수
- 폰트 및 타이포그래피
- 공통 레이아웃
- 헤더 및 내비게이션
- 버튼
- 카드
- 입력창
- 탭 및 배지
- 공통 반응형 규칙

### 18.2 페이지별 CSS

페이지별 스타일은 별도 CSS 파일에 작성한다.

예시:

- `home.css`
- `benefit-list.css`
- `benefit-detail.css`
- `application-status.css`

페이지별 CSS에서는 공통 컴포넌트의 디자인을 임의로 재정의하지 않는다.

### 18.3 디자인 토큰

가능한 모든 크기 및 색상은 공통 CSS 변수로 관리한다.

예시:

```css
:root {
  --layout-max-width: 1280px;
  --header-height: 72px;

  --radius-sm: 6px;
  --radius-md: 8px;
  --radius-lg: 12px;

  --space-xs: 4px;
  --space-sm: 8px;
  --space-md: 16px;
  --space-lg: 24px;
  --space-xl: 32px;
  --space-xxl: 48px;

  --font-size-caption: 0.75rem;
  --font-size-small: 0.875rem;
  --font-size-body: 1rem;
  --font-size-card-title: 1.125rem;
  --font-size-section-title: 1.375rem;
  --font-size-page-title: 1.75rem;
  --font-size-banner-title: 1.875rem;
}
```

기존 공통 변수와 동일한 항목이 있다면 중복 선언하지 않고 통합한다.

## 19. 디자인 변경 관리

다음과 같은 변경은 개별 페이지에서 임의로 진행하지 않는다.

- 기본 색상 변경
- 폰트 변경
- 헤더 디자인 변경
- 컨테이너 최대 너비 변경
- 버튼 규격 변경
- 카드 규격 변경
- 기본 간격 규칙 변경

변경이 필요한 경우 다음 순서로 진행한다.

1. 기존 화면설계와 비교한다.
2. 공통 디자인 규칙 변경 필요성을 확인한다.
3. 디자인 가이드를 먼저 수정한다.
4. 공통 CSS에 변경 사항을 적용한다.
5. 기존 화면에 미치는 영향을 확인한다.

특정 페이지에서만 사용되는 독립적인 기능의 레이아웃은 화면설계에 따라 조정할 수 있다.

---

## 20. Codex 필수 준수사항

모든 프론트엔드 작업에서 다음 지침을 반드시 준수한다.

1. 작업 시작 전에 본 문서를 읽는다.
2. 기존 화면설계와 현재 구현 화면을 비교한다.
3. 공통 색상 팔레트 이외의 색상을 임의로 사용하지 않는다.
4. 제목, 부제목, 본문 크기를 임의로 변경하지 않는다.
5. 공통 헤더 구조와 디자인을 유지한다.
6. 카드와 버튼의 크기 및 스타일을 통일한다.
7. 페이지별 CSS에서 공통 스타일을 불필요하게 덮어쓰지 않는다.
8. 복덩이 캐릭터는 기존 원본을 사용한다.
9. 화면 최대 너비와 반응형 규칙을 준수한다.
10. 화면설계에 없는 새로운 UI 구성요소를 임의로 추가하지 않는다.
11. 새로운 디자인 패턴이 필요한 경우 기존 디자인 요소의 재사용을 우선한다.
12. 작업 완료 후 기존 디자인 규칙과 충돌하는 부분이 있는지 확인한다.

### 작업 완료 검증

- [ ] 공통 헤더 디자인 유지
- [ ] 페이지 최대 너비 1280px 준수
- [ ] 제목 및 본문 글자 크기 통일
- [ ] 지정된 색상 팔레트 사용
- [ ] 버튼 및 카드 스타일 통일
- [ ] 화면설계와 레이아웃 비교 완료
- [ ] 복덩이 캐릭터 원본 유지
- [ ] 반응형 레이아웃 확인
- [ ] 기존 페이지와 시각적 통일성 확인

**최종 원칙: 복덩이의 모든 페이지는 서로 다른 화면이 아니라 하나의 서비스에 속한 일관된 디자인 시스템으로 구현한다.**
