# 복덩이(Bokdeongi) — 페이지 및 화면 기능 명세서

**문서명:** PAGE_SPEC.md
**버전:** v1.0
**기준 문서:** 복덩이 화면설계(ver.3), 기능 명세, 유스케이스
**적용 범위:** 전체 프론트엔드 화면

---

## 1. 문서 목적

본 문서는 복덩이 웹사이트의 페이지별 화면 구성, 사용자 동작, 기능 및 페이지 이동 경로를 정의한다.

Codex는 화면을 구현하기 전에 반드시 본 문서에서 해당 페이지의 명세를 확인해야 한다.

### 기본 원칙

1. 화면설계(ver.3)를 기준으로 구현한다.
2. 사용자가 요청한 페이지만 제작한다.
3. 같은 페이지의 다른 상태는 별도 HTML로 생성하지 않는다.
4. 모든 화면에 공통 디자인 가이드를 적용한다.
5. 기능 명세와 화면설계에 없는 기능을 임의로 추가하지 않는다.
6. HTML/CSS/JavaScript의 역할을 분리한다.
7. 아직 백엔드가 연결되지 않은 기능은 명확하게 구분한다.
8. 기존 완성 페이지를 임의로 다시 제작하지 않는다.

## 2. 공통 화면 구성

### 2.1 공통 헤더

기본 페이지에는 동일한 헤더를 적용한다.

메뉴 구성:

- 홈
- 복지 혜택 찾기
- 맞춤 혜택 추천
- 신청 현황
- 쉬운 말 번역기
- 마이페이지

AI 신청 도우미는 독립적인 상단 메뉴로 추가하지 않는다.

### 2.2 공통 페이지 레이아웃

기본 구조:

1. 공통 헤더
2. 페이지별 상단 배너 또는 안내 영역
3. 메인 콘텐츠
4. 페이지별 버튼 및 보조 기능
5. 필요한 경우 공통 하단 안내

디자인 크기, 색상, 글꼴, 여백은 `DESIGN_GUIDE.md`를 따른다.

### 2.3 공통 상태 처리

데이터를 조회하는 화면은 필요한 경우 다음 상태를 지원한다.

- 최초 진입
- 로딩
- 정상 조회
- 결과 없음
- 조회 실패
- 로그인 필요

저장 기능이 있는 화면은 저장 중 중복 요청을 방지하고 실패 시 이전 데이터를 유지한다.

## 4. HOME — 홈 대시보드

**화면 ID:** HOME-UI-01
**파일명:** index.html
**참고:** 화면설계 PDF 3~4페이지
**관련 기능:** HOME-01, HOME-02, HOME-03

### 4.1 화면 목적

사용자가 받을 수 있는 복지 혜택과 신청 진행 상황을 한눈에 확인할 수 있도록 한다.

### 4.2 화면 구성

**A. 메인 배너**

- 복덩이 캐릭터 이미지
- 서비스 안내 제목
- 서비스 설명
- 바로가기 카드 3개

바로가기:

1. 복지 혜택 찾기
2. 신청 현황 확인
3. 프로필 수정하기

문구와 버튼은 HTML로 구현한다.

배너 이미지는 기존 `img/` 폴더에서 불러온다.

**B. 지원금 요약**

- 예상 지원금
- 최대 지원금
- 금액 관련 안내

**C. 이번 주 혜택 요약**

- 신규 해당 혜택
- 마감 임박 혜택
- 변경된 공고

**D. 내 신청 현황**

- 진행 중인 혜택
- 현재 신청 단계
- 진행률
- 마감일

**E. 신청 일정 캘린더**

- 월간 달력
- 접수 시작일
- 신청 마감일
- 결과 발표일
- 날짜별 일정 목록

### 4.3 사용자 동작

- 복지 혜택 찾기 → benefit-list.html
- 신청 현황 확인 → application-status.html
- 프로필 수정하기 → my-page.html
- 맞춤 혜택 요약 → benefit-recommend.html
- 캘린더 날짜 선택 → 해당 날짜 일정 표시
- 일정 선택 → benefit-detail.html

### 4.4 화면 상태

- 로그인 사용자: 개인화 정보 표시
- 비로그인 사용자: 로그인 안내
- 프로필 미완료: 프로필 입력 안내
- 일정 없음: 빈 일정 안내
- 조회 실패: 재시도 안내

### 4.5 데이터

- 사용자 프로필
- 예상·최대 지원금
- 주간 혜택 요약
- 진행 중 신청 목록
- 캘린더 일정
- 데이터 기준 시각

## 5. AUTH — 로그인 및 회원가입

### 5.1 로그인

**화면 ID:** AUTH-UI-01
**파일명:** login.html
**참고:** 화면설계 PDF 2~3페이지

화면 구성:

- 복덩이 로고 및 캐릭터
- 이메일 입력창
- 비밀번호 입력창
- 비밀번호 표시 전환
- 로그인 버튼
- 카카오 로그인 버튼
- 회원가입 링크

화면 동작:

- 입력값 검증
- 로그인 성공 → index.html
- 회원가입 → signup-account.html
- 로그인 실패 안내
- 인증 취소 및 오류 처리

### 5.2 회원가입

회원가입은 4단계로 구성한다.

| 단계 | 파일명 | 기능 |
|---|---|---|
| 1 | signup-account.html | 이메일, 비밀번호 등 계정 정보 |
| 2 | signup-consent.html | 필수·선택 동의 |
| 3 | signup-profile.html | 거주지, 소득, 가구 정보 등 |
| 4 | signup-complete.html | 가입 완료 및 홈 이동 |

공통 요구사항:

- 현재 단계 표시
- 이전/다음 이동
- 필수값 검증
- 오류 메시지
- 저장 상태 유지

회원가입 관련 화면은 화면설계 PDF 28~32페이지를 참고한다.

## 6. BEN — 복지 혜택 찾기

**화면 ID:** BEN-UI-01~03
**파일명:** benefit-list.html
**참고:** 화면설계 PDF 4~6페이지

### 6.1 화면 구성

- 공통 헤더
- 복지 혜택 찾기 안내 배너
- 검색창
- 추천 검색어 및 해시태그
- 검색 필터
- 정렬 선택
- 검색 결과 목록
- 혜택 상세 보기 버튼
- 관심 저장 버튼

### 6.2 검색 필터

- 신청 상태
- 복지 분야
- 지원 대상

상세 항목은 화면설계와 기능 명세를 따른다.

### 6.3 화면 상태

**검색 전**

- 검색 시작 안내
- 복덩이 캐릭터 이미지

**검색 결과 있음**

- 검색 결과 건수
- 활성 필터
- 혜택 정보 카드
- 정렬 기능

**검색 결과 없음**

- 검색 결과 없음 안내
- 유사 해시태그 추천
- 검색어 수정 및 필터 초기화

조회 실패는 결과 없음과 별개의 상태로 처리한다.

### 6.4 사용자 동작

- 검색어 입력 → 결과 갱신
- 필터 선택 → 결과 갱신
- 정렬 변경 → 목록 재정렬
- 해시태그 선택 → 같은 태그 목록
- 상세 보기 → benefit-detail.html
- 관심 저장 → 로그인 사용자 저장

**검색 전·검색 결과·검색 결과 없음은 하나의 HTML 파일에서 구현한다.**

**파일명:** benefit-detail.html

- 혜택명
- 안내 배너
- 관심 저장
- 공유

- 신청 도우미 시작 버튼

- 지원 금액
- 개인 자격 판정

**탭 2: 원문 보기**

- 공식 공고문
- 원문 미리보기
- PDF 다운로드
- 공식 페이지 바로가기

**탭 3: 필요 서류**

- 필수 서류
- 선택 서류

- 신청 절차

- 방문 신청 안내

- 탭 선택 → 해당 콘텐츠 표시
- 관심 저장 → 저장 상태 변경

- 신청 도우미 → assist-eligibility.html 또는 저장된 단계
- 공식 신청 → 실제 공고의 접수처

신청 기간이 종료되면 신청 관련 버튼을 비활성화한다.

- 오류 및 재시도 안내

각 단계는 별도의 HTML 파일로 구현한다.

- 추가 질문 답변
- 자격 재판정

## 15. 백엔드 연동 기준

현재 프론트엔드 개발 단계에서는 실제 백엔드 API가 연결되지 않을 수 있다.

이 경우:

1. 필요한 화면에만 Mock Data를 사용한다.
2. 샘플 데이터와 실제 데이터를 구별한다.
3. 화면 렌더링과 데이터 조회 함수를 분리한다.
4. 백엔드 API 경로를 임의로 확정하지 않는다.
5. 개인화 데이터는 로그인 및 프로필 여부에 따라 상태를 구분한다.
6. 실제 데이터와 연동할 기능을 작업 완료 보고에 정리한다.

API 명세가 확정되면 별도 API 문서를 우선하여 연동한다.
