# 정답셋 (C)

AI 추출(DATA-04 날짜, DATA-05 금액, DATA-06 중복 불가, DATA-07 서류, DATA-09 해시태그)의 정확도를 재기 위한 사람 라벨 30건.
프롬프트를 바꿀 때마다 이 정답과 비교해 점수를 낸다.

## 파일

| 파일 | 내용 | 커밋 |
| --- | --- | --- |
| `sample.py` | 원본에서 표본 30건 추출 | O |
| `samples.csv` | 표본 공고 원문 (공개 공고 데이터만) | O |
| `labels.csv` | 사람이 채우는 정답 (`posted_year`: 연도 없는 날짜의 기준 연도) | O |
| `dates_holdout.csv` | 날짜 규칙을 만들 때 안 본 직접입력 공고 30건. 원문과 날짜 정답이 한 파일 | O |
| `hashtags_seed.csv` | 해시태그 사전 초안 40개 (hashtags 테이블 초기 데이터, D-44 변경) | O |

## 실행 (레포 루트에서)

```bash
# 원본이 없으면 먼저 수집 (api_survey/README.md 참고)
python data-lab/api_survey/collect.py

python data-lab/gold_set/sample.py          # samples.csv, labels.csv 생성
python -m unittest discover -s data-lab/gold_set
```

- 신청기한 분류(api_survey 보고서 3장)별 개수를 정해서 뽑는다: 날짜(연도 포함) 6, 상시 5, 매년 반복 4, 기관별 상이 3, 나머지 분류 각 2
- 같은 분류 안에서는 지원유형이 겹치지 않게 고른다. 개인·가구 대상만 뽑는다
- 시연 공고(서비스명에 '청년', '월세')는 항상 넣는다
- seed가 같으면 항상 같은 30건이 나온다. `labels.csv`는 이미 있으면 덮어쓰지 않는다

## 라벨링 가이드 (`labels.csv`)

`samples.csv`의 원문만 보고 채운다. 원문에 없는 내용은 추측하지 말고 비워 둔다.

| 칸 | 값 | 규칙 |
| --- | --- | --- |
| apply_start / apply_end / result_date | `2026-03-02` 또는 `2026-03` | 아래 "날짜 기준 v2"를 따른다. 월까지만 있으면 `2026-03`처럼 월까지만(첫날·말일로 채우지 않음). 시작만 있으면 start만, "~까지"만 있으면 end만. 상반기·하반기처럼 기간이 여러 개면 `2025-11-12;2026-05-18`처럼 `;`로 순서를 맞춰 모두 적는다 |
| date_status | `PARSED` / `ALWAYS` / `NO_APPLICATION` / `VARIES` / `CHECK_NOTICE` | 날짜를 적었으면 PARSED. 상시·연중은 ALWAYS. 신청 불필요는 NO_APPLICATION, API 신청기한유형이 "접수기관별상이"면 VARIES (D-51). 나머지는 CHECK_NOTICE |
| date_precision | `DAY` / `MONTH` / 비움 | 적은 날짜가 일까지 있으면 DAY, 월까지만 있으면 MONTH. 화면에는 "2026년 4월~11월 (정확한 날짜는 공고 확인)"처럼 보여 준다. 날짜를 안 적었으면 비움 |
| recurring_yearly | `Y` / 비움 | "매년", "해마다", "연초", "연말"이 있으면 Y. "4월"처럼 월만 있는 건 반복이 아니다(`period_class`의 "매년 반복"은 자동 분류라 무시) |
| date_source_quote | 원문 그대로 | 날짜 판단의 근거가 된 부분을 복사 |
| max_amount | 숫자(원) | "최대 20만 원" → `200000`. 현물·서비스는 비움 |
| amount_period | `MONTH` / `YEAR` / `ONCE` | 월 단위 / 연 단위 / 1회 |
| annual_amount | 숫자(원) | 연간 환산. 월 20만 원 × 12개월 → `2400000`. 기간을 모르면 비움 |
| amount_source_quote | 원문 그대로 | 금액 근거 부분 |
| exclusion_text | 원문 그대로 | "다른 OO 지원과 중복 불가" 같은 문구. 없으면 비움 |
| self_docs | `주민등록등본;임대차계약서` | 신청자가 직접 내는 서류만, `;`로 구분. 공무원 확인 서류는 뺀다 |
| hashtags | `월세;생활비;현금지원;청년` | `hashtags_seed.csv`의 name만 1~5개, `;`로 구분. 분야 최대 2개 + 지원형태 1개 + 대상 최대 2개. **분야는 API `서비스분야` 기준**(생활안정→생활비 등, `hashtags_seed.csv` 설명 참고)으로 붙이고, 서비스명에 월세·전세·창업·장학금 같은 말이 있으면 그 태그를 앞에 더한다 |
| labeler / memo | 이름 / 자유 | 애매한 점은 memo에 적고 팀에서 맞춘다 |

### 날짜 기준 v2

| # | 경우 | 값 | 예시 |
| --- | --- | --- | --- |
| 1 | 연도 + 월(초·중·말)까지만 | PARSED + MONTH | "2026. 4월 ~ 11월" → `2026-04`~`2026-11` |
| 1 | 날짜가 분명한 기간이 여러 개 (상반기·하반기, 1차·2차) | PARSED, 기간을 모두 `;`로 | "상반기 : 2025. 11. 12. ~ 11. 26. 하반기 : 2026. 5. 18. ~ 6. 2." (결정 ⓐ) |
| 1 | 기간 판단 기준이 서로 겹침 (날짜 + 수시·추가 모집 등) | CHECK | "2026. 8. 3. ~ 9. 4. ※ 미달 시 연중 수시 모집", "(추가모집 별도 진행)" |
| 2 | 연도 없이 월(일)만 | 게시 연도(`수정일시`의 연도)를 붙여 PARSED | "매년 1월~3월"(수정일시 2026) → `2026-01`~`2026-03` |
| 3 | 예산 소진 시까지, 사람마다 신청 기간이 다름(상대 기간) | CHECK | "당해연도 예산 소진 시까지", "출생일로부터 3개월 이내" |
| 4 | "연초(당해년도 1월)"처럼 월 숫자가 있음 | PARSED | → `2026-01`~`2026-01` (D-66) |
| 4 | "연초", "연말"처럼 월 숫자가 없음 | CHECK | "매년 연초" (D-66) |
| 4 | "예정"이라는 말이 있음 (날짜가 분명해도) | CHECK | "매년 1월(예정)", "2025년 2~4월중 신청예정", "'26.7.1.~12.31.(하반기) ※'27년 모집은 별도 공고 예정" |
| 5 | "전년도", "해당연도", "사업연도"처럼 다른 해가 기준 | CHECK | "사업시행 전년도 11월~12월" |
| 6 | 신청 불필요 | NO_APPLICATION | "신청불필요", "별도 신청절차 없음" (D-51) |
| 6 | API 신청기한유형 "접수기관별상이" | VARIES | (D-51). 원문에 "OO별로 다를 수 있음"만 있는 직접입력은 CHECK |
| 7 | 그 밖의 예외 | CHECK | "무인민원발급기 운영시간", "공모기간내" |

- `labels.csv`와 `dates_holdout.csv`의 `posted_year` 칸에 기준 연도를 적어 둔다. 검증 모듈(DATA-03)이 이 값으로 연도까지 확인한다
- 원문에 연도가 없으면 비우지 않고 공고의 등록·수정일 기준으로 연도를 추정한다. 실제로는 `samples.csv`의 `modified_at`(API `수정일시`), `dates_holdout.csv`의 `posted_year`를 쓴다. API `등록일시`는 대부분 2021년 일괄 등록이라 쓰지 않는다
- 이 기준은 백엔드 날짜 규칙 추출기(`ApplyPeriodExtractor`)와 같다. 기준을 바꾸면 라벨과 규칙 코드를 같은 PR에서 고친다

### 신청 기간이 여러 개일 때 (결정 ⓐ)

- 라벨에는 원문의 기간을 모두 적는다
- DB에는 신청 기간을 하나만 저장한다. 저장할 때 오늘 기준으로 **진행 중인 기간 → 없으면 다음에 올 기간 → 둘 다 없으면 가장 최근에 끝난 기간** 하나를 고른다 (`ApplyPeriodExtractor.pickPeriod`)
- 예: "상반기(3~5월 중), 하반기(9~11월 중)", 오늘 2026-11-13 → `2026-09`~`2026-11`

## 라벨 확인 규칙

- LLM(Claude·Gemini)이 채우거나 바꾼 라벨은 C가 한 줄씩 원문과 직접 대조해 확인한다. 확인하기 전에는 정답으로 쓰지 않는다
- 기준이 바뀌어 라벨을 고치면 memo 끝에 `[기준] 이전값 → 새값`을 남긴다 (예: `[D-51] ALWAYS → NO_APPLICATION`)
